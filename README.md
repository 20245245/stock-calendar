# 증시 캘린더

고정 주소: https://20245245.github.io/stock-calendar/

증시 일정과 개인 투자 노트를 함께 사용하는 웹 앱입니다. 화면과 공개 일정은 GitHub Pages, 로그인한 사용자의 비공개 노트는 Supabase에 저장합니다. 로그인 없이도 기기 노트를 작성할 수 있습니다.

## 사용

- 기본 화면은 공식 날짜가 확인된 핵심 일정만 표시합니다.
- 관심 후보, 확인 필요, 원문 보관도 별도로 확인할 수 있습니다.
- 날짜와 시각은 KST로 표시합니다. 현지 거래일·종일 행사는 별도 명시합니다.
- 페이지를 열거나 `최신 일정 확인`을 누르면 공통 JSON을 캐시 없이 불러옵니다. 창에 다시 돌아올 때도 최근 확인 이후 1분이 지났으면 갱신합니다.
- 내 일정·개인 메모·개인 수정·숨김은 이 브라우저에만 저장됩니다. GitHub나 다른 기기로 전송되지 않습니다.
- `개인 백업`과 `개인 백업 복원`으로 개인 자료를 다른 기기로 옮길 수 있습니다. 백업 파일에는 개인 메모가 있으므로 저장소에 커밋하지 마세요.
- 공통 일정에서 수정한 항목은 `내 변경`으로 표시됩니다. `공통 일정 복원`은 개인 수정만 제거하고 최신 공통 일정으로 되돌립니다. 개인 메모는 유지합니다.
- 공개 공통 일정은 GitHub 파일을 수정해야 다른 기기에도 반영됩니다. 웹 화면의 편집은 개인 변경입니다.

## 다음 일정 업데이트

이 채팅에서 자료와 함께 다음처럼 요청하세요.

> GitHub 20245245/stock-calendar의 공통 일정을 업데이트해 주세요. 핵심/관심/확인 필요 기준을 유지하고 공식 날짜를 확인해 한국시간으로 반영해 주세요.

업데이트할 원본은 `data/calendar.json`입니다. `revision`을 새 값으로 바꾸고 `updatedAt`을 갱신하세요. 이벤트 ID는 유지하고 중복·폐기 원문은 같은 ID의 `archived:true`로 보관합니다. 과거 일정도 남겨 둡니다.

```sh
node scripts/sync-seed.cjs
node tests/store.test.cjs
node --check app.js
```

`sync-seed`는 오프라인/로컬 파일용 fallback인 `calendar-data.js`를 갱신합니다. 이 파일은 생성 결과이므로 데이터를 직접 따로 관리하지 않습니다. `data/legacy-baseline.json`은 기존 버전에서 바꾼 개인 자료를 판별하는 고정 비교 자료입니다.

일정 선별 규칙과 공식 출처·확인 범위는 [SOURCES.md](SOURCES.md)를 참고하세요. 일정은 바뀔 수 있으며 자동으로 공식 기관을 조사·수집하는 서비스는 아닙니다.

## 로컬 확인

프로젝트 폴더에서 정적 HTTP 서버를 열고 `index.html`을 확인하세요. 파일을 직접 열면 온라인 JSON을 불러오지 못할 수 있으며 이때 배포된 기본 자료를 표시합니다.

## 저장 구조

- `data/calendar.json`: 모든 기기에서 읽는 공개 공통 일정
- `calendar-data.js`: 공개 JSON의 로컬/오프라인 fallback
- `store.js`: 공통 자료와 개인 변경을 합치는 로직
- `app.js`: 렌더링·편집·공통 자료 갱신
- `localStorage[stock-calendar-private-v3]`: 개인 일정·수정·메모·숨김만 저장

공통 자료 전체를 브라우저 저장본으로 덮어쓰지 않습니다. 이전 v1/v2 저장 데이터가 같은 주소에 있으면 원본을 별도 키에 백업한 뒤 사용자 변경만 개인 자료로 옮깁니다. 주소가 달라지면 기존 내보내기 JSON을 `개인 백업 복원`으로 가져올 수 있습니다.

## 배포

GitHub Settings → Pages에서 main 브랜치의 루트(/)를 배포 대상으로 사용합니다. `.nojekyll`로 일반 정적 파일을 제공합니다. main 변경이 배포되면 같은 주소에서 새 공통 일정을 불러옵니다.


## 투자 노트 (2026-11-11)

- 상단 **노트 쓰기** 또는 일정을 눌러 넓은 문서 편집기를 엽니다. 날짜만 정한 자유 노트도 만들 수 있습니다.
- 본문은 일반 텍스트/Markdown입니다. 붙여넣은 문단을 유지하고 소제목·굵게·목록·인용 도구와 읽기 모드를 지원합니다. 붙여넣은 HTML은 실행하지 않습니다. 이미지 첨부·HTML 서식 편집은 현재 지원하지 않습니다.
- 입력이 멈춘 뒤 약 0.6초 후 IndexedDB에 자동 저장합니다. 화면의 저장 상태를 확인하세요. 계정 노트는 잠시 뒤 또는 ‘지금 동기화’로 서버에 업로드합니다. 네트워크가 끊기면 기기에서 작성을 계속하고 재연결 시 재시도합니다. 앱을 처음 여는 데는 인터넷 연결이 필요합니다.
- **동기화 설정 → 로그인 메일 받기**: 메일에 인증 코드가 있으면 코드를 입력합니다. 링크만 있으면 이메일 버튼의 로그인 링크 주소를 복사해 같은 입력란에 붙여넣습니다. 기본 Supabase 이메일 템플릿을 바꾸지 않아도 사용할 수 있도록 지원합니다. 로그인 링크를 직접 눌러 다른 주소로 이동할 필요가 없습니다.
- 같은 이메일로 로그인한 기기에서 같은 계정 노트를 볼 수 있습니다. 기기 노트는 자동 업로드하지 않으며, **이 기기 노트 가져오기**로 로그인한 계정에 복사합니다. 원본은 유지합니다. 기존 v3 개인 메모는 처음 열 때 기기 노트로 복사하고 원본도 남겨 둡니다.
- 기존 ‘개인 일정 백업’과 새 **노트 백업**은 서로 다릅니다. 노트 백업에는 현재 글과 이 기기의 복구 이력이 포함됩니다. 기기 변경 전 노트 백업을 받아 둘 수 있습니다. 복원 전 현재 노트의 백업 파일도 내려받습니다. 겹치는 ID는 별도 복원본으로 보존합니다.
- **이전 내용 복구**에서 기기 이력과 로그인 상태라면 서버의 최근 50개 이력을 볼 수 있습니다. 기기 복구 지점은 첫 수정·약 1분 간격·저장/닫기 시점에 생성합니다. 모든 키 입력의 실행 취소 이력은 아닙니다.
- 삭제는 휴지통으로 이동하며 **내 노트 → 휴지통 → 복구**로 되살릴 수 있습니다. UI에 영구 삭제 기능은 없습니다.
- 여러 기기의 수정이 겹치면 서버의 글을 덮어쓰지 않고 **기기 수정본**을 별도 노트로 보존합니다.
- 클라우드에는 노트(본문·제목·기록일·연결 일정 ID·휴지통 상태)와 수정 이력을 저장합니다. 일정의 개인 날짜 수정·숨김은 기존처럼 기기에만 저장됩니다.
- Supabase 기본 메일 서비스의 발송 대상·빈도 제한이 적용될 수 있습니다. 여러 사용자에게 서비스할 때는 별도 SMTP 설정이 필요합니다. 노트 파일 백업은 사용자가 내려받는 방식이며, 별도 외부 저장소로의 정기 자동 백업은 구성하지 않았습니다.

### 운영 및 검증

`cloud-config.js`에는 프로젝트 URL과 공개 클라이언트 키만 저장합니다. 서비스 역할 키나 사용자 토큰을 커밋하지 않습니다. `supabase/journal.sql`은 비공개 테이블과 쓰기 함수를 구성한 마이그레이션입니다. 사용자별 읽기는 RLS로 제한하고 쓰기 함수는 JWT 사용자 ID와 수정 번호를 검사합니다. 익명 접근과 다른 계정의 읽기, 수정 충돌 및 이력 저장을 실제 데이터베이스에서 트랜잭션 후 롤백하는 방식으로 검증했습니다. 인증 사용자에게만 허용한 SECURITY DEFINER 함수는 쓰기 및 이력 보존을 위한 의도된 구성입니다.

```sh
node tests/journal.test.cjs
node tests/store.test.cjs
node --check app.js
node --check journal.js
node --check journal-cloud.js
```
